# 前端数据优化方案

> SACC 报名系统前端设计（[返回前端导航](index.md)）

面向报名系统的高频场景：配置读取、名单大数据量、实时状态变更、动态表单。

## 一、优化原则

- **分层缓存**：只读配置长缓存，动态数据短缓存或直查
- **请求下推**：分页 / 筛选 / 聚合在服务端完成，前端不拉全量
- **按域拆分**：查询缓存与客户端状态分离，互不耦合

## 二、数据请求层

| 方案 | 说明 |
|---|---|
| 查询缓存 | 引入 TanStack Query 管理服务端状态：缓存、去重、重试、失效、loading 态；Zustand 只保留客户端状态（表单草稿、UI 开关） |
| 请求去重 | 相同 key 并发请求合并为一次；组件卸载时取消未完成请求（AbortController） |
| 分页下推 | 列表统一 `page/pageSize` + 筛选条件序列化，服务端过滤后返回 |
| 错误处理 | 统一 `{ code, data, message }`；401 登出、403 无权限提示、网络失败重试（指数退避） |

## 三、缓存策略

| 数据 | 类型 | 策略 |
|---|---|---|
| `form_field` / `group` / `activity` 详情 | 只读配置 | Query 长 `staleTime` + localStorage 持久化，首屏先用缓存渲染再校验 |
| 活动列表 / 大厅 | 低频变更 | 短缓存（如 60s），下拉刷新失效 |
| 名单 / 审核 / 审计 | 动态数据 | 不缓存，筛选下推服务端分页 |
| 通知未读数 | 实时 | WebSocket 推送，失败回退 30s 轮询 |
| HTTP 层 | 列表接口 | 支持 ETag / `If-None-Match`（后端配合），304 直接复用 |

## 四、大数据量场景

| 场景 | 方案 |
|---|---|
| 名单表格 | 服务端分页 + 虚拟滚动（antd Table `virtual`）+ 表头冻结；列多时按 `field_key` 懒展开 |
| 导出 | 对接后端 `wasm_export_chunk(offset, limit)` 分块拉取 → 流式拼接下载，避免一次性占内存 |
| 数据看板 | 聚合统计下推服务端，前端仅渲染图表，不做明细聚合 |
| 审计日志 | 时间范围 + 操作人筛选强制服务端过滤 |

## 五、实时数据

| 场景 | 方案 |
|---|---|
| 通知未读 / 审核结果 / 候补递补 | WebSocket（宿主实现）推送事件 → 更新 store 与角标；断线重连 + 轮询兜底 |
| 报名截止倒计时 | 接口返回服务端时间戳，本地定时器按差值计算，避免客户端时钟偏差 |
| 名额进度 | 活动详情轮询（短间隔）或 WS 推送 |

## 六、动态表单性能

- 字段联动显隐：只挂载可见字段，显隐切换才渲染对应控件，避免大表单全量渲染
- 校验防抖：输入触发校验延迟执行，减少无效计算
- 草稿自动保存：防抖（如 2s）写入 localStorage，网络失败时本地恢复，上报时再合并
- 上传：图片压缩 + 缩略图预览，原图后台上传

## 七、资源与构建

| 项 | 方案 |
|---|---|
| 路由懒加载 | `React.lazy` + `Suspense`，按路由分包，管理端 / 报名端独立 chunk |
| antd 按需 | antd 5 默认 tree-shaking，避免全局引 CSS |
| 图表按需 | DataBoard 页面懒加载，图表库不进主包 |
| 骨架屏 | 工作台 / 名单等加载态用 Skeleton 占位 |

## 八、状态管理边界

| 类型 | 归属 | 示例 |
|---|---|---|
| 服务端状态 | TanStack Query | 活动列表、分组树、字段定义、名单数据 |
| 客户端状态 | Zustand | 认证信息、表单草稿、当前步骤、UI 开关、通知未读数 |

## 九、监控与验收指标（可选）

- 指标：首屏可交互时间、接口耗时 P95、列表页滚动帧率、请求失败率
- 轻量埋点：上报到 `audit_log` 之外的前端日志（或本地缓存），不做重量级监控
