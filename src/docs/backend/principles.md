# 设计要点

> [返回后端导航](index.md)

- **定义与数据分离**：表单结构在配置层，填写结果在数据层；字段只追加软删，历史 `registration_data` 引用始终有效。
- **动态字段**：报名信息由管理员配置，新增字段无需改表结构；`validation` 支持条件联动。
- **账号安全**：密码仅存哈希 + 盐；连续登录失败锁定；支持密码重置令牌。
- **名额并发**：报名用条件更新（已报名数 < `max_slots` 才成功）防超卖；满员置候补（`status=5`），有名额自动递补。
- **审核流**：提交后置待审核，审核通过 / 驳回（含理由），结果经 `notification` 通知用户。
- **修改 / 取消**：截止前可编辑（`allow_modify` 控制），取消释放名额。
- **权限控制**：`user_role` 限定角色与分组管理范围，审核操作记录到 `audit_log`。
- **软删除**：`activity` / `form` / `group` / `form_field` 均用 `is_deleted` 软删，历史报名数据全部保留；`user` 禁止删除，仅禁用账号。
- **字段变更策略**：`form_field` 只追加、不物理删除、`field_key` 不可变更。
- **预填规则**：基础资料取 `user`，其余按 `field_key` 匹配 `user_common_info`，冲突以本次填写为准；`field_key` 命名空间化防跨活动误匹配。
- **通知机制**：站内信直写库；邮件由宿主 SMTP 发送（`send_status` 跟踪、失败重试）；订阅提醒由宿主定时任务在活动开始前触发。
- **权限判定**：`user_role.group_id` 为 NULL 表示全部范围，否则以递归 CTE 展开该分组及子分组判定，活动属于任一授权分组即放行；命中任一角色即授权。
- **密码重置**：`reset_token` 经 `user.email` 发送，校验 `reset_expire` 后更新密码；登录失败达上限锁定至 `lock_until` 自动解锁。
- **配置预留**：活动级 / 全局键值配置，`config_type` 区分布尔/数字/文本/JSON，key 用常量枚举登记，新增功能无需改表结构。
- **高频开关固化**：`need_review`、`allow_modify` 等影响核心流程的开关直接作为 `activity` 正式字段，键值表只留给低频/扩展配置。
- **配置可追溯**：配置变更记录到 `audit_log`，配置表带 `updated_at` 便于追踪。
- **通知偏好**：`user_notify_pref` 控制每类通知的渠道，未配置走活动 `notify_channel` 默认渠道。
- **凭证核销**：`receipt_no` 生成二维码，签到写入 `checkin_time`。
- **模板复用**：`form_template` 以 JSON 快照保存字段定义，新活动一键套用。
- **活动形式**：`activity_type` 区分线下 / 线上 / 混合；场地、参会链接、签到方式按形式走活动配置；分阶段活动用多表单表达。
