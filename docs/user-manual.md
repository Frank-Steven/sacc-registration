## 一、系统简介

SACC 报名系统是一个全功能的活动报名管理平台，支持以下核心能力：

- **活动管理**：创建/编辑/发布活动，支持线下、线上和混合模式
- **表单设计器**：自定义报名表单，支持文本、数字、单选、多选、日期等字段类型
- **报名与审核**：分步报名表单，支持草稿保存、审核队列、驳回重提
- **名额管理**：防超卖机制、候补队列、自动递补
- **签到核销**：现场扫码、线上自助、动态码三种签到模式
- **数据导出与统计**：CSV 导出、状态分布、字段分布、趋势折线
- **通知系统**：站内信 + 邮件双通道，按类型/渠道个性化偏好
- **多级权限**：超级管理员、活动管理员、审核员三级角色体系

## 二、环境要求与安装

### 环境要求

| 工具 | 版本 | 用途 |
|---|---|---|
| Node.js | >= 20 LTS | 宿主服务与前端 |
| yarn | >= 1.22 | 依赖管理 |
| wasi-sdk | >= 25 | 编译 backend.wasm |
| CMake | >= 3.24 | 后端构建 |

### 安装步骤

```bash
# 1. 克隆仓库
git clone https://github.com/Frank-Steven/sacc-registration.git
cd sacc-registration

# 2. 安装依赖
yarn install

# 3. 编译后端 WASM
cmake -S backend -B backend/build -DCMAKE_BUILD_TYPE=Debug
cmake --build backend/build --target backend_wasm

# 4. 配置环境变量
cp .env.example .env
# 编辑 .env，至少配置 JWT_SECRET（生产环境必须使用强随机值）
```

### 环境变量说明

| 变量 | 说明 | 默认值 |
|---|---|---|
| `DB_PATH` | SQLite 数据库文件路径 | `./data/sacc.db` |
| `JWT_SECRET` | 会话 token 密钥（**生产必填**） | 开发期自动生成临时密钥 |
| `WASM_PATH` | backend.wasm 路径 | `./backend/build/backend.wasm` |
| `PORT` | 监听端口 | `3000` |
| `SMTP_HOST/PORT/USER/PASS` | 邮件发送（可选） | 未配则仅站内信 |

### 启动服务

```bash
# 一键启动开发环境（宿主 + 前端开发服务器）
yarn dev

# 宿主服务：http://localhost:3000
# 前端开发服务器：http://localhost:5173（/api 自动代理到宿主）
```

首次启动时，系统会自动初始化数据库（建表、插入角色种子数据等），无需手动操作。

## 三、创建第一个超级管理员

> **重要：** 系统不会自动创建超级管理员。首次部署后，需要手动完成以下步骤。

### 步骤总览

```
注册普通用户 → 通过 API 授予超级管理员角色 → 登录使用管理后台
```

### 步骤 1：注册一个普通用户

通过前端注册页面，或使用 curl 调用注册接口：

```bash
curl -X POST http://localhost:3000/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"your_password","name":"管理员"}'
```

注册成功后，记录返回的 `uid`（用户 ID），后续步骤需要用到。

### 步骤 2：授予超级管理员角色

系统内置三个角色（由数据库迁移自动创建）：

| role_id | 角色名称 | 说明 |
|---|---|---|
| 1 | 超级管理员 | 全系统管理权限 |
| 2 | 活动管理员 | 分组范围内活动管理 |
| 3 | 审核员 | 分组范围内审核操作 |

**第一个超级管理员必须通过直接操作数据库来创建**，因为「授权角色」接口本身要求操作者已是超级管理员。

有两种方式可以完成：

#### 方式 A：使用辅助脚本（推荐）

项目提供了 `scripts/bootstrap-admin.js` 脚本，自动完成注册 + 授权：

```bash
node scripts/bootstrap-admin.js
```

按提示输入用户名和密码即可。脚本会：
1. 注册新用户（如用户名已存在则跳过注册）
2. 将该用户提升为超级管理员（role_id=1，全范围）
3. 输出操作结果

#### 方式 B：手动操作数据库

如果项目脚本不可用，可以直接操作 SQLite 数据库：

```bash
# 1. 先通过 API 注册用户，获取 uid（见步骤 1）

# 2. 通过 sqlite3 直接写入 user_role 表
sqlite3 data/sacc.db "INSERT INTO user_role (uid, role_id, group_id) VALUES (<你的uid>, 1, NULL);"
```

其中：
- `role_id = 1` 表示超级管理员
- `group_id = NULL` 表示全范围（不限定任何分组）

### 步骤 3：验证

用刚创建的账号登录前端，访问管理后台（`/admin`），确认可以正常进入系统管理页面。

### 安全提醒

- 超级管理员拥有**全部权限**，包括分组管理、角色授权、账号管理、数据备份等
- 系统**不允许撤销最后一个超级管理员**（会返回错误），防止管理权丢失
- 生产环境务必配置强随机的 `JWT_SECRET`
- 建议为第一个超管账号使用强密码，启用后通过管理后台「代重置密码」功能为其他管理员分配密码

## 四、角色与权限说明

### 角色权限矩阵

| 操作 | 超级管理员 | 活动管理员 | 审核员 | 普通用户 |
|---|:---:|:---:|:---:|:---:|
| 分组树管理 | 全部 | 绑定活动 | - | - |
| 活动创建/编辑/发布 | 全部 | 授权范围内 | 只读 | - |
| 表单/字段管理 | 全部 | 授权范围内 | 只读 | - |
| 模板管理 | 全部 | 授权范围内 | - | - |
| 活动配置 | 全部 | 授权范围内 | 只读 | - |
| 系统配置 | 读写 | - | - | - |
| 角色授权 | 授权/撤销 | - | - | - |
| 账号管理 | 全部 | - | - | - |
| 数据统计/备份 | 全部 | - | - | - |
| 审核报名 | - | 授权范围内 | 授权范围内 | - |
| 签到核销 | - | 授权范围内 | 授权范围内 | - |
| 报名 | - | - | - | 全部 |
| 查看通知 | - | - | - | 全部 |

### 分组范围机制

- 活动管理员和审核员的权限**限定在其被授权的分组范围内**
- 授权分组**包含子分组**（递归生效）
- 超级管理员**忽略分组条件**，始终拥有全系统权限
- 活动必须绑定到分组，才能被活动管理员/审核员看到

## 五、超级管理员操作指南

### 5.1 分组管理

路径：`/admin/groups`

分组是权限范围的基础单位，用于组织活动和限定管理员权限。

- **创建分组**：点击「新建分组」，输入名称，选择父分组（留空则为顶级）
- **编辑分组**：点击分组名称或编辑按钮，修改名称或移动父分组
- **删除分组**：点击删除按钮（有子分组时禁止删除，需先删除子分组）

### 5.2 角色授权

路径：`/admin/roles`

为其他用户授予管理角色：

1. 在用户列表中找到目标用户
2. 点击「授权」，选择角色（活动管理员或审核员）
3. 选择授权分组范围（活动管理员和审核员需选择分组；超管忽略分组）
4. 确认授权

**撤销角色**：在用户角色列表中点击「撤销」按钮。

> 注意：无法撤销最后一个超级管理员。

### 5.3 账号管理

路径：`/admin/accounts`

- **搜索用户**：支持按用户名、姓名、学号、手机号模糊搜索
- **禁用/启用账号**：点击状态切换按钮（禁止禁用自己）
- **代重置密码**：点击「重置密码」，系统生成 12 位随机密码，新密码显示在弹窗中

### 5.4 系统配置

路径：`/admin/system-config`

管理全局系统配置项（如站点名称、签到密钥等）。

### 5.5 审计日志

路径：`/admin/audit-logs`

查看所有管理操作的审计记录，支持按操作人、操作类型、时间范围筛选。

### 5.6 数据治理

路径：`/admin/governance`

- **数据库统计**：查看各表行数、软删除计数、数据库文件大小
- **备份管理**：手动触发备份、查看历史备份列表、下载备份文件

## 六、活动管理员操作指南

> 活动管理员只能操作被授权分组范围内的活动。

### 6.1 创建活动

路径：`/admin/activities/new`

1. 填写活动基本信息（名称、类型、描述）
2. 设置名额上限（`max_slots`）
3. 选择是否需要审核（`need_review`）
4. 绑定分组（**必须绑定至少一个授权分组**，否则无法创建）
5. 保存为草稿

### 6.2 设计报名表单

路径：`/admin/activities/:id` → 表单标签页

1. 创建表单（一个活动可有多个表单组）
2. 添加字段，支持类型：
   - **文本**（type=0）：可设正则校验、最小长度
   - **数字**（type=1）：可设最小值/最大值
   - **单选**（type=2）：配置选项列表
   - **多选**（type=3）：配置选项列表，可设最少选择项数
   - **日期**（type=4）
   - **文件**（type=5）
   - **单选-服从调剂**（type=6）
   - **多行文本**（type=7）
3. 设置必填/选填、校验规则

> **注意：** 活动发布后，字段仅允许追加新选项，不可删除已有选项或修改字段类型。

### 6.3 发布活动

活动状态流转：**草稿(0) → 进行中(1) → 已截止(2) → 已结束(3)**

- 草稿状态下可自由编辑
- 发布（状态设为 1）后，活动在报名端可见（需已绑定分组）
- 已截止后不可再接受新报名
- 只有草稿状态的活动可以删除

### 6.4 审核报名

路径：`/admin/activities/:id/review`

- 查看待审核报名列表
- 逐条查看详情，选择「通过」或「驳回」
- 驳回时可填写审核评语
- 通过后报名状态变为「已通过」，占用名额

### 6.5 签到核销

路径：`/admin/activities/:id/checkin`

三种签到模式（在活动配置中设置）：

| 模式 | 说明 |
|---|---|
| 现场扫码（默认） | 管理员扫描报名者凭证二维码或输入凭证号签到 |
| 线上自助 | 报名者自行在手机端点击签到 |
| 线上动态码 | 主办方展示大屏动态码，报名者输入 6 位动态码签到 |

### 6.6 数据导出与统计

- **CSV 导出**：`/admin/activities/:id/registrations` → 导出 CSV（Excel 兼容，含 BOM）
- **数据看板**：`/admin/activities/:id/stats` → 状态分布、名额使用率、字段分布、报名趋势
- **分块导出**：支持游标分页的大批量数据导出

### 6.7 模板管理

路径：`/admin/templates`

- 从已有活动保存表单模板
- 新建活动时套用模板，快速生成表单结构

## 七、普通用户操作指南

### 7.1 注册与登录

访问系统首页，点击「注册」创建账号：
- 用户名：3~32 位字母、数字或下划线
- 密码：8~128 位

登录后自动跳转到工作台。

### 7.2 浏览与报名活动

路径：`/activities`

1. 在活动大厅浏览可报名活动（左侧分组树可筛选）
2. 点击活动查看详情（名额、报名时间、活动说明等）
3. 点击「报名」进入分步表单
4. 填写各字段信息，可随时保存草稿
5. 完成所有步骤后点击「提交」

### 7.3 报名状态说明

| 状态 | 说明 |
|---|---|
| 填写中 | 草稿，可继续编辑 |
| 待审核 | 已提交，等待管理员审核 |
| 已通过 | 审核通过，获得参加资格 |
| 未通过 | 审核驳回，可查看驳回原因并修改后重新提交 |
| 候补 | 名额已满，排队等待（有取消时自动递补） |
| 已取消 | 主动取消报名 |

### 7.4 我的工作台

路径：`/workbench`

- 按状态分组展示所有报名记录
- 草稿可点击继续填写
- 候补显示排队名次
- 已取消的报名可重新报名

### 7.5 报名凭证

报名通过后，可在报名详情页查看：
- 凭证编号（如 `R1-5`）
- 凭证二维码（现场签到时出示）

### 7.6 通知中心

路径：`/notifications`

- 查看所有通知（报名成功、审核结果、活动提醒等）
- 未读通知显示角标
- 支持全部标记已读
- 通知偏好可在个人设置中按类型/渠道（站内信/邮件）配置

### 7.7 个人资料

路径：`/profile`

- 编辑姓名、学号、邮箱等基础资料
- 管理常用信息（报名时可快速填充）
- 设置语言偏好（中文/英文）
- 上传头像（data URL 格式）
- 配置通知偏好和界面偏好

## 八、常见问题

### Q1：忘记密码怎么办？

点击登录页的「忘记密码」，输入注册邮箱，系统会发送重置令牌。输入令牌和新密码完成重置。

> 注意：当前版本重置令牌直接显示在响应中（开发阶段），生产环境接入邮件后将改为邮件发送。

### Q2：报名提交后可以修改吗？

已提交的报名不可直接修改。如果活动允许修改（`allow_modify=true`），可以在报名详情页点击编辑。否则需先取消再重新报名。

### Q3：候补什么时候能递补？

当有已通过的报名者取消时，候补队列中排名最前的报名者自动递补为「待审核」状态。递补后需等待管理员审核通过。

### Q4：活动管理员看不到某个活动？

请检查：
1. 该活动是否已绑定到管理员被授权的分组
2. 分组授权是否包含子分组（授权一个分组会递归包含其所有子分组）

### Q5：如何备份数据库？

超级管理员可在「数据治理」页面手动触发备份，或通过 API：

```bash
curl -X POST http://localhost:3000/api/admin/backups \
  -H "Authorization: Bearer <token>"
```

备份文件存储在 `data/backup/` 目录下。系统也会在数据库迁移前自动备份。

### Q6：登录失败 5 次后被锁定怎么办？

系统连续登录失败 5 次后会锁定账号 15 分钟。可以：
- 等待 15 分钟后自动解锁
- 联系超级管理员通过「代重置密码」功能解锁（同时重置密码）
