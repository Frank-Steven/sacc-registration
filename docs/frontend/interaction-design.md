# 功能交互设计

> SACC 报名系统前端设计（[返回前端导航](index.md)）

## 一、关键流程

**1. 注册 / 登录**
- 注册：表单（username + 密码 + 基础资料）→ 创建 `account` / `user` → 自动登录跳工作台
- 登录：校验密码 → 失败计数达上限提示锁定至 `lock_until` → 成功写入 token
- 忘记密码：输入 `user.email` → 发送 `reset_token` → 链接进入重置页 → 设置新密码

**2. 报名**
- 进入详情 → 报名按钮（时间 / 名额 / 唯一性校验，不满足置灰并提示原因）
- 预填：基础资料（`user`）+ 常用信息（`user_common_info`）按 `field_key` 匹配
- 分步填写：步骤条 + 每步自动保存草稿（`current_step`）；再次进入提示"继续上次填写"
- 提交：整体校验 → 条件更新名额 → 按 `need_review` 反馈"待审核"或"报名成功"
- 成功页：`receipt_no` + 二维码

**3. 审核**
- 队列 → 详情抽屉（字段明细）→ 通过 / 驳回（理由必填）
- 批量：勾选 → 批量通过 / 驳回（同理由）
- 驳回后用户收到通知 → "修改并重新提交"（预填原内容，状态 3→1）

**4. 候补与递补**
- 满员提交 → 提示"已加入候补队列" + 当前排名（`queue_no`）
- 有名额自动递补 → 通知状态变更

**5. 修改 / 取消**
- 修改（`allow_modify`）：详情 → 编辑 → 保存（已提交记录状态回退）
- 取消：二次确认（提示名额释放 / 候补者不再递补）→ 确认

**6. 签到核销**
- 线下（`checkin_mode=0`）：扫码 `receipt_no` → 校验 → 写入 `checkin_time` → 成功 / 已签 / 无效提示
- 线上（`checkin_mode=1`）：活动开放后一键签到

**7. 通知触达**
- 站内信：顶栏未读角标 → 通知中心
- 邮件：按 `user_notify_pref` 偏好 + 活动 `notify_channel` 决定

**8. 表单设计器**
- 拖拽（移动端触控长按）排序 → 字段配置面板（标签 / 类型 / 必填 / 选项 / 默认值 / 校验 / 联动 / 可见性）→ 实时预览 → 保存（只追加，下线走软删提示）

## 二、状态机 → UI 映射

对应 [数据层状态机](../backend/data-layer.md#状态机)：

| status | 用户端展示 | 管理端展示 | 可操作 |
|---|---|---|---|
| 0 填写中 | 草稿，继续填写 | 草稿 | 用户编辑 |
| 1 待审核 | 待审核 | 审核队列 | 审核员通过 / 驳回 |
| 2 已通过 | 成功 + 凭证 | 名单"已通过" | 签到 |
| 3 未通过 | 驳回理由 + 重新提交 | 驳回 | 用户重提 |
| 4 已取消 | 已取消 | 已取消 | - |
| 5 候补 | 候补 + 排名 | 候补列表 | 管理员调整 |

## 三、全局交互约定

- 列表统一：筛选 + 分页 + 导出 CSV
- 删除 / 取消 / 批量操作均二次确认
- 表单即时校验，提交前整体校验
- 请求错误统一 toast + 错误码映射（401 跳登录、403 提示无权限）
